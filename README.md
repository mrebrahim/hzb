# منظومة التنظيم — قياس أداء وتحفيز الأعضاء والأمانات

نسخة أولى (MVP) من "منظومة قياس أداء وتحفيز للتنظيم": تطبيق ويب عربي يتثبت على الموبايل (PWA)، مبني بـ Next.js وSupabase.

## فيه إيه

| للعضو | للمنسق/الأمين | للأدمن |
|---|---|---|
| عروض مهام مناسبة ليه مع سبب الترشيح، يقبل أو يعتذر من غير خصم | لوحة مؤشرات لكل محافظة/مركز: نشط، بيقل، خامل، قبول العروض، مهام معتمدة، حضور، نقاط/عضو | تعيين المنسقين ووحداتهم |
| تسليم تقرير ميداني بصورة وموقع (اختياري) | إنشاء مهام من قوالب، وتوزيعها تلقائياً | تصحيح النقاط بحركة عكسية + سجل تدقيق |
| تسجيل حضور بمسح QR بيتغير كل 30 ثانية + تأكيد الموقع | مراجعة التقارير واعتمادها (النقاط مش بتتحسب قبل الاعتماد) | |
| مستوى وسلّم ترقّي وترتيب نسبي داخل وحدته | ترتيب الوحدات (منافسة فرق مش أفراد) | |
| مركز خصوصية: سحب الموافقة وتحميل البيانات | "نجم الشهر": بوست جاهز وشهادة PDF | |

### محرك التوزيع (قابل للتفسير)
قيود صلبة: العضو داخل الوحدة، موافقته سارية، مش موقوف، عنده مهارة من المطلوبة، وتحت الحد الأقصى لعدد مهامه المفتوحة.
وبعدها درجة = 0.35 مهارة + 0.20 توافر + 0.15 دافع (VFI) + 0.15 موثوقية + 0.15 عدالة − إرهاق.
المهمة بتتعرض على ضعف العدد المطلوب. وكل 15 دقيقة (pg_cron) بيحصل: انتهاء العروض وإعادة التوزيع، وتذكير قبل الموعد بـ 24 ساعة، وتصعيد المهام المتأخرة للمنسق، وتحديث حالة النشاط (نشط ≤ 10 أيام، بيقل 10–21، خامل > 21) مع تنبيه المنسق ورسالة إعادة تنشيط.

### النقاط
- دفتر حركات `point_ledger` غير قابل للتعديل أو الحذف (trigger)، وكل حركة ليها مفتاح idempotency.
- صغيرة 10 / متوسطة 25 / كبيرة 50، و+10% لو اتعتمدت من أول مرة، وحد أقصى 150 نقطة في اليوم من المهام.
- المستويات: عضو (0) ← عضو نشط (100) ← منسّق شارع/قرية (300) ← مرشّح لأمانة (800).
- مفيش نقاط تتحول لفلوس، ومفيش ترتيب علني للأفراد على مستوى الجمهورية.

### الخصوصية والأمان
- RLS على كل الجداول؛ المنسق بيشوف بس الأعضاء اللي في نطاق وحدته وما تحتها.
- موافقة مكتوبة إلكترونية وقت التسجيل (قانون 151 لسنة 2020)، وسجل موافقات بيتحفظ كتاريخ كامل.
- الموقع بيتاخد لحظة الحضور بس. مفيش تعرف على الوجه، ومفيش "درجة ولاء".
- صور الإثبات في bucket خاص بروابط موقّعة.

## التشغيل

```bash
cp .env.example .env.local
npm install
npm run dev
```

الـ migrations في `supabase/migrations` ومطبّقة بالفعل على مشروع Supabase `hzb`.
**أول حساب يتسجل بيبقى أدمن تلقائياً**، وكل اللي بعده أعضاء.

### الأدوار
| الدور | يقدر يعمل إيه |
|---|---|
| أمين | كل حاجة في نطاقه: المؤشرات، والمهام، والمراجعة، والفعاليات، ونقل الأعضاء وتغيير حالتهم، وإضافة مراكز ووحدات |
| أمين مساعد | المؤشرات، والمهام، والمراجعة، والفعاليات، ومشاهدة الأعضاء (من غير نقل أو تعديل) |
| عضو | مهامه، ونقاطه، وحضوره، وخصوصيته |
| أدمن النظام | تعيين الأدوار وتصحيح النقاط |

### الديمو
تنظيم تجريبي منفصل ("حزب تجريبي") فيه 3 محافظات و9 مراكز و60 عضو و8 أسابيع نشاط. بيترجع لحالته الأصلية كل يوم الساعة 3 الفجر (`select public.seed_demo()`).
صفحة الدخول فيها زراير دخول مباشر (تتقفل بـ `NEXT_PUBLIC_DEMO=off`). كلمة السر لكل الحسابات `Demo@2026`:
- `amin@demo.hzb.app`: أمين التنظيم
- `assistant@demo.hzb.app`: أمين مساعد القاهرة
- `member@demo.hzb.app`: عضو في مدينة نصر

## قبل أي استخدام حقيقي
- **الاستضافة:** قاعدة البيانات دلوقتي في `eu-west-1` (أيرلندا)، يعني نقل بيانات حساسة برّه مصر، وده محتاج تصريح مسبق. للإنتاج: Supabase self-hosted على سيرفر في مصر، أو تصريح من مركز حماية البيانات الشخصية. راجع محامي.
- **واتساب:** مفيش أي تكامل مع Evolution API/Baileys عمداً، لأن سياسة واتساب بتمنع الأحزاب والجهات اللي بتقدم خدمات سياسية. القنوات المقترحة: إشعارات داخل التطبيق (موجودة)، وبعدها Web Push وبوت Telegram وSMS.
- فعّل SMTP مخصص في Supabase Auth (المدمج محدود الإرسال)، وفعّل MFA للمنسقين.
